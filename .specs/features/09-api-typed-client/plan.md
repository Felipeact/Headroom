# 09 - Typed API client

## Problem

The web app has no way to call the API. The first spec that does (10, login) would have to write the request and response types by hand, and AGENTS.md forbids that: "Every call to the API goes through the typed client in `lib/api/`. Never hand-write request types." Hand-written types drift: when a route in `services/core` changes, nothing tells the web app, and the mismatch shows up only at runtime, in front of a user. `contracts/openapi.json` and `frontend/lib/api/schema.d.ts` are named in AGENTS.md as generated files, but neither exists yet, and nothing would catch them going stale. The source gives no evidence beyond the roadmap's build order: specs 10, 11 and every later screen depend on this one.

When this ships, a developer changes a route, runs two commands, and the web app's types follow. If they forget either command, CI fails. Server code calls the API through one client whose paths, parameters and responses are type-checked, and the browser never sees the API's address.

## Flow

This reuses the FastAPI `app` object in `app/main.py`, which already builds its OpenAPI schema (`app.openapi()`), the existing `web` and `api` CI jobs (AD-004), and the `app/dev/` page pattern (AD-014). No new CI job and no new API route.

1. developer runs `uv run python -m app.export_openapi` (from `services/core`) -> `app.export_openapi` (new, door 1) imports `app.main` (exists, AD-001: no database needed) and writes `app.openapi()` to `contracts/openapi.json` (door 1)
2. developer runs `npm run api:types` (from `frontend`) -> `openapi-typescript` (new dependency, door 2) reads `../contracts/openapi.json` and writes `lib/api/schema.d.ts` (door 2)
3. a server component or server action imports `lib/api/client.ts` (new, door 3) -> `openapi-fetch` (new dependency, door 3) sends the request to `API_URL` (door 3); the response is typed by `schema.d.ts` `paths`
4. out: `app/dev/api-check` (new page, AD-014) renders the `GET /healthz/live` result; in production builds it 404s
5. CI `api` job (exists) reruns step 1 and fails if `contracts/openapi.json` differs; CI `web` job (exists) reruns step 2 and fails if `lib/api/schema.d.ts` differs (door 4)

| stored data | nothing to migrate |

## Relations

None - no stored-data shape change.

## Surface

None - nothing consumed outside. No API route is added; `/dev/api-check` is a development-only page that 404s on staging and production (AD-014). The two commands are developer tools, covered in `Observable`.

## Landing

| One-way door | Literal shape | Alternative rejected |
| --- | --- | --- |
| 1. OpenAPI export | module `app/export_openapi.py`, run as `uv run python -m app.export_openapi` from `services/core`; writes `<repo root>/contracts/openapi.json` (path resolved from the module file, not the cwd) as `json.dumps(app.openapi(), indent=2, ensure_ascii=False) + "\n"` with `\n` line endings; key order is FastAPI's, no `sort_keys`; prints the written path and exits `0` | fetching `/openapi.json` from a running server: needs a server in CI and races its startup. `sort_keys=True`: reorders paths and properties away from the declaration order the generated types and docs follow. Writing relative to the cwd: running from the repo root would write a second, stray copy |
| 2. Type generation | devDependency `openapi-typescript`; script `"api:types": "openapi-typescript ../contracts/openapi.json -o lib/api/schema.d.ts"` in `frontend/package.json`; output committed and excluded from ESLint if its rules flag generated code | a generator that emits a full SDK (orval, openapi-generator): generated runtime code instead of types only, and a larger surface to review on every regeneration. Committing only `openapi.json` and generating types at build: the spec requires both committed, and a reviewer sees type changes in the diff |
| 3. The client | runtime dependencies `openapi-fetch` and `server-only`; `lib/api/client.ts` starts with `import "server-only"`, exports `api` built by `createClient<paths>({ baseUrl })` where `baseUrl` is `process.env.API_URL`, read when a request is made, not at import; when `API_URL` is unset the call throws `Error("API_URL is not set")`. Callers use `api.GET("/healthz/live")` and read `{ data, error, response }` | `NEXT_PUBLIC_API_URL`: inlines the address into the browser bundle, and AGENTS.md says the browser never calls the API. A default of `http://localhost:8000`: a staging build missing the variable would silently call itself. Reading `API_URL` at import: `next build` imports server modules, so a build without the variable would fail. A hand-written `fetch` wrapper: hand-written request types, which AGENTS.md forbids |
| 4. CI drift check | `api` job, after `uv run pytest`: `uv run python -m app.export_openapi` then `git diff --exit-code -- ../../contracts/openapi.json`. `web` job, after `npm ci`: `npm run api:types` then `git diff --exit-code -- lib/api/schema.d.ts`. Both on the existing triggers | a third job that installs both toolchains: a new check name that branch protection does not require (AD-004), so a failure would not block a merge. Comparing in one job only: a stale `schema.d.ts` with a fresh `openapi.json` would pass |

- Doors 1 to 4 reach past this feature (every later endpoint and screen uses them) and become AD-015 to AD-018 in `.specs/STATE.md` `## Decisions` once the plan is approved.
- The test page's layout, the client's file split, whether `createApiClient` is exported for tests, and the Playwright wiring are reversible and settled in the diff.

## Criteria

### S1: Generated contract and types (P1)

A developer regenerates the API contract and the web types with two commands, and both are committed.

**Acceptance Criteria**

1. WHEN `uv run python -m app.export_openapi` runs from `services/core` with no `DATABASE_URL` set THEN it SHALL exit `0` and write `contracts/openapi.json` at the repository root, whose parsed content equals `app.main.app.openapi()`
2. WHEN `uv run python -m app.export_openapi` runs twice in a row THEN the two outputs SHALL be byte-identical, end with exactly one `\n`, and contain no `\r`
3. The file `contracts/openapi.json` SHALL contain the paths `/healthz/live` and `/healthz/ready`
4. WHEN `npm run api:types` runs from `frontend` THEN it SHALL exit `0` and write `lib/api/schema.d.ts` exporting a `paths` type with the key `"/healthz/live"`
5. WHEN both commands run on a clean checkout of the feature's last commit THEN `git status --porcelain -- contracts/openapi.json frontend/lib/api/schema.d.ts` SHALL print nothing (the committed files are current)

**Independent test:** run both commands, then `git diff --exit-code` on the two files exits `0`.

### S2: Server-only typed client (P1)

Server code calls the API through one typed client, and the browser never gets it.

**Acceptance Criteria**

6. WHEN server code calls `api.GET("/healthz/live")` with `API_URL` pointing at a running API THEN it SHALL resolve with `data` equal to `{ status: "ok" }` and `response.status` `200`
7. The client SHALL send the request to `${API_URL}/healthz/live` (proved with an injected fake `fetch`, no network)
8. IF `API_URL` is unset WHEN a request is made THEN the client SHALL throw `Error` with message `API_URL is not set`, and importing `lib/api/client.ts` without `API_URL` SHALL NOT throw
9. IF `lib/api/client.ts` is imported from a file marked `"use client"` THEN `npm run build` SHALL fail
10. The type checker SHALL reject `api.GET("/healthz/nope")` (a path absent from `paths`) and reading `data.missing` on the `/healthz/live` result (proved with `@ts-expect-error` lines that `npm run typecheck` must accept)
11. The production build output in `.next/static` SHALL NOT contain the string `API_URL` or the configured `API_URL` value

**Independent test:** `npm run typecheck && npm test` passes; a scratch `"use client"` import makes `npm run build` fail.

### S3: Test page shows the live result (P1)

Done when: "A test page shows the result of `GET /healthz/live` through the typed client."

**Acceptance Criteria**

12. WHEN `/dev/api-check` is opened in development with the API running THEN the page SHALL show the heading `API check` and the text `status: ok` obtained through `lib/api/client.ts`
13. IF the API is unreachable or answers with a non-2xx status THEN `/dev/api-check` SHALL show `API unreachable` and the HTTP status when one exists, and SHALL NOT throw to the error boundary
14. WHILE `NODE_ENV` is `production` the page SHALL call `notFound()` and make no request to the API (AD-014)
15. The page SHALL have no axe violations, no horizontal scroll at 375 pixels wide, and its heading SHALL be reachable by keyboard-only navigation without a focus trap

**Independent test:** `npm run test:e2e -- api-check` starts the web app and the API and passes.

### S4: CI fails on a stale contract (P1)

Done when: "Changing an endpoint without regenerating the files makes CI fail."

**Acceptance Criteria**

16. IF an endpoint in `services/core` changes and `contracts/openapi.json` is not regenerated THEN the CI `api` job SHALL fail at the drift step
17. IF `contracts/openapi.json` changes and `frontend/lib/api/schema.d.ts` is not regenerated THEN the CI `web` job SHALL fail at the drift step
18. WHEN both files are current THEN both CI jobs SHALL pass, with job ids still `web` and `api` (AD-004)

**Independent test:** on a scratch pull request, rename the `/healthz/live` response field without regenerating; the `api` check goes red.

## Out of scope

| Excluded | Why |
| --- | --- |
| calling any `/v1` route | none exists yet; spec 10 adds the first |
| attaching a Clerk session token to requests | spec 10 (login) owns authentication |
| a typed error helper that narrows problem details | no route returns a domain error yet; the first spec that needs one adds it |
| `API_URL` on Railway staging | the only caller 404s on staging; see Assumptions |
| browser-side API calls | forbidden by AGENTS.md |

## Assumptions

| Assumption | Chosen default | Rationale | Confirmed? |
| --- | --- | --- | --- |
| when staging's `web` gets `API_URL` | spec 10, as `http://${{api.RAILWAY_PRIVATE_DOMAIN}}:<port>` once the private-network port is confirmed | no staging page calls the API in this spec, and the private-network address needs its own proof (IPv4/IPv6 binding, port) that belongs with the first real call | n |
| how AC 16-18 are proved | a scratch pull request into `development` that changes an endpoint without regenerating, showing the red check, then closed and its branch deleted; plus the green run on `development` after the feature is pushed | the Done-when names CI itself; a local rerun of the steps proves the commands, not the workflow. Needs a branch and a push, which AGENTS.md says to ask for | n |
| `noUncheckedIndexedAccess`, recommended by openapi-ts | not enabled | it changes type checking across existing code, which this spec does not need; a separate change can turn it on | n |
| copy on `/dev/api-check` | English literals in the page, not `messages/en.json` | developer-only page, same precedent as `/dev/sentry-check` (spec 07) | n |
| loading state on `/dev/api-check` | none of its own: the page awaits the call on the server and renders once | a developer tool with one fast request; adding Suspense adds code for no reader | n |
